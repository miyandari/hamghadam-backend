# سامانه مدیریت مشارکت‌های فرهنگی «هم‌قدم»

سامانه وب چنددانشگاهی برای مدیریت برنامه‌های فرهنگی، ثبت‌نام دانشجویان، بررسی سوابق فرهنگی، انتخاب مستقیم مدیر، قرعه‌کشی وزنی، رزرو گروهی، فهرست انتظار، اعلان‌ها، بازخورد و گزارش‌گیری.

> این بسته فقط پوشه `backend/` را در بر می‌گیرد. فایل `docker-compose.yml` و فایل `.env` واقعی در ریشه پروژه کاربر قرار دارند و نباید با این بسته جایگزین شوند.

## ۱. فناوری‌ها

- PHP 8.4 و Laravel 13
- Laravel Sanctum برای احراز هویت API
- PostgreSQL 16 برای پایگاه داده
- Redis 7 برای cache و session/cache backend
- Blade، JavaScript و CSS برای پنل مدیریت و درگاه دانشجویی
- Docker Compose برای اجرای محیط توسعه

## ۲. راه‌اندازی محیط توسعه

### پیش‌نیازها

- Windows 11
- Docker Desktop با WSL2 فعال
- PowerShell
- مرورگر وب

### اجرای پروژه

از مسیر ریشه پروژه (پوشه‌ای که `docker-compose.yml` در آن قرار دارد) اجرا کنید:

```powershell
docker compose up -d
docker compose ps
```

سرویس‌های مورد انتظار:

- `app` روی پورت 8000
- `postgres` روی پورت 5432
- `redis` روی پورت 6379

سپس از داخل پوشه ریشه پروژه:

```powershell
docker compose exec app php artisan optimize:clear
docker compose exec app php artisan migrate
docker compose exec app php artisan storage:link
```

نشانی‌ها:

- پنل مدیریت: http://localhost:8000/admin
- درگاه دانشجویی: http://localhost:8000/student
- بررسی سلامت Laravel: http://localhost:8000/up

برای خاموش‌کردن سرویس‌ها:

```powershell
docker compose stop
```

برای راه‌اندازی مجدد:

```powershell
docker compose start
```

**هشدار پایگاه داده:** از `docker compose down -v`، `php artisan migrate:fresh` یا حذف volumeهای PostgreSQL استفاده نکنید؛ این دستورات می‌توانند اطلاعات واقعی را حذف کنند. مهاجرت‌های جدید این نسخه افزایشی هستند و با `php artisan migrate` اجرا می‌شوند.

## ۳. نصب نسخه ZIP

1. از پوشه `C:\Projects\hamghadam\backend` نسخه پشتیبان تهیه کنید.
2. ZIP را استخراج کنید.
3. محتویات پوشه `backend` داخل ZIP را در `C:\Projects\hamghadam\backend` جایگزین کنید.
4. فایل `.env` فعلی خود را حفظ کنید؛ فایل `.env.example` جایگزین آن نیست.
5. از مسیر ریشه پروژه اجرا کنید:

```powershell
docker compose exec app composer dump-autoload
docker compose exec app php artisan migrate
docker compose exec app php artisan optimize:clear
docker compose exec app php artisan storage:link
```

اگر migration با خطا مواجه شد، ادامه ندهید و متن کامل خطا را نگه دارید. دیتابیس را از نو نسازید.

## ۴. نقش‌ها و حدود دسترسی

| نقش | مسئولیت |
|---|---|
| مدیر ارشد (`super_admin`) | تعریف دانشگاه‌ها و کاربران، تخصیص مدیران فرهنگی، مشاهده گزارش‌های کلان و نظارت بر برنامه‌ها |
| مدیر فرهنگی (`cultural_manager`) | ایجاد و انتشار برنامه‌های دانشگاه خود، بررسی اطلاعات و سوابق دانشجو، تنظیم عوامل قرعه‌کشی، انتخاب مستقیم در سهمیه، اجرای قرعه‌کشی، مدیریت بازخورد و آلبوم |
| دانشجو (`student`) | تکمیل پروفایل، ارسال سوابق فرهنگی، مشاهده برنامه‌ها، ثبت‌نام انفرادی یا گروهی، لغو ثبت‌نام و مشاهده اعلان‌ها |
| ناظر (`observer`) | نقش تعریف‌شده برای دسترسی نظارتی؛ نماها و مجوزهای تفصیلی ناظر در توسعه تکمیلی قابل گسترش است |

مدیر ارشد برنامه فرهنگی ایجاد نمی‌کند؛ ایجاد و ویرایش برنامه در اختیار مدیر فرهنگی است. مدیر ارشد از بخش گزارش‌ها و نظارت برای مشاهده وضعیت کلان استفاده می‌کند.

## ۶. امکانات پیاده‌سازی‌شده در این نسخه

### ۶.۱ مدیریت سازمانی و کاربران

- ثبت و ویرایش دانشگاه و فعال/غیرفعال‌سازی آن
- ایجاد کاربر و تخصیص نقش و دانشگاه
- فعال و غیرفعال‌سازی حساب کاربری
- جلوگیری از ویرایش/غیرفعال‌سازی حساب مدیر ارشد اصلی از مسیر مدیریت عادی
- محدودسازی مدیر فرهنگی به دانشگاه‌هایی که به آن‌ها تخصیص داده شده است

### ۶.۲ برنامه‌های فرهنگی

- تعریف برنامه با دسته‌هایی مانند اردو، گل‌گشت، کارگاه، همایش و مراسم
- وضعیت‌های پیش‌نویس، منتشرشده، لغوشده و پایان‌یافته
- ویرایش برنامه پیش‌نویس و تغییر وضعیت
- تعیین ظرفیت و بازه ثبت‌نام
- فرم تاریخ شمسی با انتخاب‌گر داخلی و بدون وابستگی به CDN؛ تاریخ‌ها در API به میلادی تبدیل می‌شوند
- ساعت در فرم نمایش داده نمی‌شود و تاریخ‌ها در ساعت `00:00:00` ثبت می‌شوند
- نمایش نوار پیشرفت هنگام درخواست‌های API در پنل مدیریت

### ۶.۳ پروفایل و سوابق دانشجو

- نمایش نوار پیشرفت واقعی و پویا برای تکمیل ۵ فیلد اصلی پروفایل دانشجو؛ درصد با تغییر فیلدها و پس از بارگذاری اطلاعات ذخیره‌شده به‌روز می‌شود.
- ثبت اطلاعات دانشجویی و قرارگرفتن درخواست جدید در وضعیت «در انتظار تأیید»
- تأیید یا رد پروفایل توسط مدیر فرهنگی دانشگاه مربوطه
- ثبت سوابق فعالیت فرهنگی، عضویت در تشکل، فعالیت داوطلبانه، تقدیر و موارد دیگر
- امکان ثبت توضیح و بازه زمانی سابقه
- تأیید یا رد سوابق توسط مدیر فرهنگی؛ سابقه تأییدشده برای بررسی عوامل قرعه‌کشی قابل مشاهده است

### ۶.۴ عوامل و قرعه‌کشی وزنی

- مدیر برای هر برنامه عنوان عامل و ضریب تأثیر را مستقل تعریف می‌کند.
- عامل‌ها شرط حداقل امتیاز یا مانع ثبت‌نام نیستند.
- مدیر فرهنگی برای هر متقاضی، عامل‌های قابل اعمال را بررسی و تأیید می‌کند؛ عامل‌های شناخته‌شده مانند عضویت تشکلی، فعالیت فرهنگی، داوطلبی و تقدیر می‌توانند بر اساس سوابق تأییدشده دانشجو به‌صورت خودکار تشخیص داده شوند. عامل‌های اختصاصی دیگر با تأیید مدیر اعمال می‌شوند.
- ضریب دانشجو از حاصل‌ضرب ضرایب عامل‌های قابل اعمال محاسبه می‌شود؛ ضریب پایه ۱ است. عامل دستی تکراری با تشخیص خودکار دوباره محاسبه نمی‌شود.
- اگر عنوان عامل تعریف‌شده توسط مدیر شامل «اولین» یا «نخستین» باشد، سامانه سابقه ثبت‌نام قطعی/منتخب دانشجو در برنامه‌های هم‌دسته قبلی را بررسی می‌کند و در صورت نداشتن سابقه، ضریب آن عامل را اعمال می‌کند.
- انتخاب وزنی بدون جایگزینی انجام می‌شود و اندازه گروه در ظرفیت مصرفی لحاظ می‌شود.
- نتیجه قرعه‌کشی همراه با snapshot عوامل، وزن‌ها، منتخبین و فهرست انتظار ذخیره می‌شود.
- برای جلوگیری از تغییر ناخواسته نتیجه، اجرای مجدد قرعه‌کشی برای برنامه‌ای که قبلاً قرعه‌کشی شده، مسدود است.

**توجه:** ضرایب به‌صورت ضربی ترکیب می‌شوند. برای مثال ضرایب ۱٫۲ و ۱٫۵، وزن ۱٫۸ ایجاد می‌کنند. این عدد احتمال تضمینی نیست؛ شانس نسبی انتخاب در قرعه‌کشی وزنی است.

### ۶.۵ سهمیه انتخاب مستقیم مدیر

- مدیر در تعریف برنامه تعداد مجوزهای انتخاب مستقیم را تعیین می‌کند.
- انتخاب مستقیم از طریق فهرست متقاضیان انجام می‌شود.
- تعداد افراد انتخاب‌شده (اعضای گروه به تعداد نفرات) از سهمیه کسر می‌شود.
- انتخاب مستقیم علاوه بر سهمیه، ظرفیت واقعی برنامه را نیز کنترل می‌کند.

### ۶.۶ ثبت‌نام گروهی و فهرست انتظار

- ایجاد گروه توسط سرگروه و تولید کد دعوت
- پیوستن اعضا به گروه با کد دعوت
- کنترل فعال‌بودن ثبت‌نام گروهی و حداکثر تعداد اعضا
- در قرعه‌کشی، گروه به‌عنوان یک واحد انتخاب می‌شود و همه اعضای گروه با هم انتخاب یا در انتظار قرار می‌گیرند.
- ثبت‌نام انفرادی در صورت تکمیل ظرفیت، در فهرست انتظار ثبت می‌شود.
- با لغو ثبت‌نام قطعی، نفر بعدی فهرست انتظار در صورت وجود ثبت‌نام متناظر به ظرفیت ارتقا پیدا می‌کند.

### ۶.۷ اعلان‌ها، گزارش‌ها، آلبوم و بازخورد

- اعلان داخلی برای کاربران و شرکت‌کنندگان رویداد
- اعلان نتیجه قرعه‌کشی و قرارگیری در فهرست انتظار
- داشبورد تعداد برنامه‌ها، ثبت‌نام‌ها، فهرست انتظار و بازخوردها
- گزارش وضعیت ثبت‌نام و میانگین امتیازهای ارزیابی
- ساخت آلبوم، بارگذاری تصویر و کنترل سطح دسترسی
- ثبت بازخورد پس از پایان برنامه و تأیید نمایش توسط مدیر

## ۷. APIهای اصلی

پیشوند همه مسیرها `/api/v1` است. مسیرهای نیازمند ورود با `auth:sanctum` محافظت می‌شوند.

| حوزه | مسیرهای مهم |
|---|---|
| احراز هویت | `POST /login`، `POST /logout`، `GET /profile` |
| دانشگاه | `GET /universities`، `POST /universities`، `PUT /universities/{id}` |
| کاربر | `GET /users`، `POST /users`، `PUT /users/{id}` |
| دانشجو | `GET/POST/PUT /student`، `GET /students/pending`، `PATCH /students/{id}/moderate` |
| سوابق فرهنگی | `GET/POST /student/cultural-records`، `PATCH /student-cultural-records/{id}/moderate` |
| برنامه | `GET /events`، `GET /managed-events`، `POST /events`، `PUT/PATCH /events/{id}` |
| ثبت‌نام | `POST /events/{id}/register`، `GET /my-registrations`، `DELETE /registrations/{id}` |
| گروه | `POST /events/{id}/groups`، `POST /groups/join`، `GET /my-groups` |
| عوامل قرعه‌کشی | `GET /events/{id}/lottery-applicants`، `POST /events/{id}/lottery-factor-awards` |
| قرعه‌کشی | `POST /events/{id}/run-lottery`، `GET /events/{id}/lottery-results` |
| سهمیه مدیر | `POST /events/{id}/registrations/{registration}/manager-approve` |
| گزارش | `GET /reports/dashboard`، `GET /reports/events/{id}` |
| اعلان | `GET /notifications`، `POST /events/{id}/notifications` |
| آلبوم | `GET/POST /events/{id}/albums` و مسیرهای media |
| بازخورد | `POST /events/{id}/feedback`، `PATCH /events/{id}/feedback/{feedback}` |

## ۹. روند کاری پیشنهادی

1. مدیر ارشد دانشگاه‌ها را تعریف می‌کند.
2. مدیر ارشد حساب مدیر فرهنگی هر دانشگاه را ایجاد و نقش او را تخصیص می‌دهد.
3. دانشجو وارد درگاه `/student` می‌شود و پروفایل دانشجویی را تکمیل می‌کند.
4. مدیر فرهنگی پروفایل دانشجو و سپس سوابق فرهنگی ارسال‌شده را بررسی می‌کند.
5. مدیر فرهنگی برنامه را تعریف می‌کند، ظرفیت، بازه ثبت‌نام، سهمیه مستقیم، رزرو گروهی و عوامل ضریب را تنظیم و برنامه را منتشر می‌کند.
6. دانشجویان ثبت‌نام انفرادی یا گروهی انجام می‌دهند.
7. مدیر فرهنگی عامل‌های مرتبط با هر متقاضی را بررسی و تأیید می‌کند.
8. مدیر می‌تواند از سهمیه مستقیم استفاده کند و سپس قرعه‌کشی وزنی را اجرا کند.
9. سامانه منتخبین و فهرست انتظار را ثبت و اعلان داخلی ارسال می‌کند.
10. پس از اجرا، مدیر گزارش، بازخورد و آلبوم تصاویر را مدیریت می‌کند.

docker compose ps

## ۱۱. Git و نگهداری نسخه

مخزن Git این پروژه در پوشه `backend` قرار گرفته است. برای مشاهده وضعیت، از همان پوشه اجرا کنید:

```powershell
git status --short --branch
git remote -v
```

قبل از commit:

```powershell
git add .
git diff --cached
git commit -m "Complete cultural participation workflows"
```

فایل `.env` در `.gitignore` قرار دارد؛ با این حال همیشه خروجی `git status` و `git diff --cached` را بررسی کنید تا رمز، کلید API، اطلاعات شخصی یا فایل محلی ناخواسته وارد مخزن نشود.

## ۱۲. موارد نیازمند اتصال/تصمیم محیطی پیش از بهره‌برداری واقعی

- **پیامک واقعی:** اعلان داخلی سامانه فعال است، اما ارسال SMS واقعی نیازمند انتخاب سرویس‌دهنده پیامک و دریافت API Key، شماره/خط ارسال و الگوی پیامک تأییدشده است. تا زمان دریافت این مشخصات، سامانه نباید ادعای ارسال پیامک واقعی داشته باشد.
- **ارسال ایمیل:** پیکربندی ایمیل در `.env` باید با SMTP یا سرویس‌دهنده واقعی تکمیل شود.
- **مدارک سوابق فرهنگی:** در این نسخه عنوان، توضیحات و بازه زمانی ثبت می‌شود؛ بارگذاری و نگهداری فایل مستندات/گواهی می‌تواند با سیاست حریم خصوصی دانشگاه تکمیل شود.
- **امنیت و انتشار عمومی:** پیش از استقرار اینترنتی، `APP_DEBUG=false`، HTTPS، سیاست پشتیبان‌گیری، محدودسازی ورود، سیاست نگهداری اطلاعات و تست نفوذ باید بررسی شوند.
- **قرعه‌کشی رسمی:** الگوریتم وزن‌دهی و snapshot نتیجه در این نسخه پیاده شده است؛ پیش از اجرای رسمی، مدیر سامانه باید قواعد حقوقی/سازمانی، نحوه رسیدگی به اعتراض، زمان قفل‌شدن فهرست متقاضیان و حضور ناظر را تصویب کند.
