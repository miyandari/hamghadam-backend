# راهنمای نصب نسخه اصلاح‌شده هم‌قدم

## جایگزینی فایل‌ها
1. از `C:\Projects\hamghadam\backend` نسخه پشتیبان بگیرید.
2. محتوای پوشه `backend` داخل ZIP را در `C:\Projects\hamghadam\backend` جایگزین کنید.
3. فایل `.env` فعلی را حفظ کنید و آن را با فایل دیگری جایگزین نکنید.
4. از PowerShell و در ریشه پروژه اجرا کنید:

```powershell
docker compose exec app composer dump-autoload
docker compose exec app php artisan migrate
docker compose exec app php artisan optimize:clear
```

این نسخه یک migration افزایشی برای افزودن `event_policies.manager_approval_quota` دارد. اجرای `migrate` فقط migrationهای اجرا‌نشده را اعمال می‌کند و داده‌های قبلی را حذف نمی‌کند.

## موارد اصلاح‌شده
- اصلاح مسیر بارگذاری کتابخانه‌های تقویم شمسی و راه‌اندازی مجدد خودکار datepicker در صورت بارگذاری دیرهنگام CDN.
- انتخاب تاریخ شمسی از فیلدهای تاریخ برنامه و ثبت‌نام.
- حذف ورودی ساعت از فرم؛ زمان هر چهار تاریخ به‌صورت ثابت `00:00:00` ارسال می‌شود.
- حذف مفهوم حداقل امتیاز ورود به قرعه‌کشی؛ سوابق دانشجو نباید به‌عنوان شرط محرومیت از ثبت‌نام استفاده شوند.
- افزودن امکان تعریف عوامل مؤثر بر ضریب شانس قرعه‌کشی برای هر برنامه به‌صورت مستقل؛ مدیر عنوان عامل و ضریب آن را وارد می‌کند و اطلاعات در `event_policies.rules.lottery_factors` ذخیره می‌شوند.
- افزودن تعداد سهمیه انتخاب مستقیم مدیر بدون قرعه‌کشی.
- افزودن امکان فعال‌سازی رزرو گروهی و تعیین حداکثر اعضای گروه.
- افزودن تنظیم فعال‌بودن قرعه‌کشی و نیاز به تأیید مدیر.
- ذخیره و بازیابی تنظیمات سیاست برنامه در API؛ ضرایب نمونه مانند عضویت تشکلی یا مشارکت فرهنگی صرفاً نمونه هستند و عنوان و مقدار واقعی را مدیر همان برنامه تعیین می‌کند.
- حفظ اصلاحات قبلی پنل مدیر ارشد، مدیریت دانشگاه و کاربران، ویرایش پیش‌نویس، تغییر وضعیت، نوار پیشرفت و اصلاح جدول `feedbacks`.
- تکمیل README اصلی با ساختار پروژه، نقش‌ها، API، دیتابیس، راه‌اندازی و دستورهای Git.

## بررسی اولیه
```powershell
docker compose exec app php artisan migrate:status
docker compose exec app php artisan optimize:clear
docker compose exec app php artisan route:list --path=api/v1
```

تقویم شمسی از CDN بارگذاری می‌شود؛ مرورگر برای نمایش آن باید به CDN دسترسی داشته باشد.

## Git
راهنمای بررسی تغییرات، commit و push به remote در فایل `README.md` بخش «ثبت نسخه در Git» آمده است. پیش از commit، حتماً `git status` و `git diff --cached` را بررسی کنید و از stage شدن `.env` یا اطلاعات محرمانه جلوگیری کنید.

## تعریف عوامل ضریب قرعه‌کشی
در فرم هر برنامه، مدیر فرهنگی می‌تواند چند عامل دلخواه تعریف کند. هر عامل شامل عنوان و ضریب عددی مثبت است (حداکثر ۱۰۰). عنوان‌ها و ضرایب در بخش JSON ستون `event_policies.rules` و مسیر `lottery_factors` ذخیره می‌شوند. برای نمونه:

```json
{
  "lottery_factors": [
    {"name": "عضویت فعال در تشکل دانشجویی", "coefficient": 1.2},
    {"name": "مشارکت در فعالیت فرهنگی", "coefficient": 1.1},
    {"name": "شرکت برای اولین بار در این نوع برنامه", "coefficient": 1.5}
  ]
}
```

این قابلیت در این نسخه، تعریف و ذخیره‌سازی ضرایب در سطح هر برنامه را فراهم می‌کند. تشخیص خودکار مصادیق برای هر دانشجو، تأیید سوابق و اعمال ضریب نهایی در الگوریتم قرعه‌کشی، مرحله اجرایی جداگانه‌ای است و در این بسته ادعا نمی‌شود که پیاده‌سازی شده است.
